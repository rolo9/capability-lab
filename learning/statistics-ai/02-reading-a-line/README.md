# 単元2　温度で予測を変えると、何がよくなるか

**実行環境**　[Docker環境構築編（Apple Silicon Mac）](../../../docs/docker-setup-mac.md)で、初回のセットアップと動作確認ができます。

[単元1](../01-observations/README.md)では、100 gのおもりを量った9回の記録で、ずれの全体平均は0 gでした。温度別に見ると20 ℃で平均−1 g、30 ℃で平均＋1 gでした。そこで今回は、**温度を知っているなら、どの温度でも0 gと予測するより、温度に応じて予測を変えた方が、記録されたずれを説明できるか**を考えます。

## 1. まず、二つの予測の意味をつかむ

同じセンサーでまた量るところを想像してください。温度は分かりますが、表示がどれだけずれるかはまだ分かりません。前回の9件を使って、予測のルールを二つ作ります。

- **平均で予測する。** 過去のずれの平均は0 gなので、温度にかかわらず予測は0 gです。これを、温度を使う価値を測るための**基準モデル**にします。
- **直線で予測する。** 25 ℃を基準に、温度が1 ℃上がるたび、予測するずれを一定量だけ増減させます。その量が**傾き**です。例えば傾きが＋0.20 g/℃なら、25 ℃より5 ℃低い20 ℃では、予測が1 g下がります。

一つの入力で数値を直線によって予測する方法を**単回帰**と呼びます。今回は温度が入力、表示値から基準の重さを引いた「ずれ」が予測したい値です。

## 2. 同じ9行を使って、傾きを決める

[単元1のCSV](../01-observations/measurements.csv)をそのまま使います。1行は1回の測定です。`temperature_c` は予測前に分かる温度なので入力に使い、`reading_g` と `reference_g` は、記録上のずれを計算するために使います。`measurement_id` はあとで元の行を見つけるための番号です。

直線を引くときは、各行で「実測のずれ − 予測したずれ」を計算します。これを**残差**と呼びます。プラスとマイナスが打ち消し合わないように、各残差を二乗して足します。この**残差の二乗和**が最も小さくなるように直線を決めるのが、**最小二乗法**です。二乗するので、大きな外れほど強く効きます。

この表では平均温度が25 ℃、平均のずれが0 gです。最小二乗法で求める直線はこの平均の点を通ります。そこで各行の温度から25 ℃、ずれから0 gを引いて、平均との差を作ります。

| 測定1で計算するもの | 値 |
| --- | ---: |
| 温度の平均との差 | 20 − 25 = −5 ℃ |
| ずれの平均との差 | (98 − 100) − 0 = −2 g |
| 二つの差を掛けた値 | (−5) × (−2) = 10 ℃·g |
| 温度の差を二乗した値 | (−5)² = 25 ℃² |

同じ計算を9行について行います。**二つの差を掛けた値の合計は30、温度の差を二乗した値の合計は150**です。前者を後者で割ると、傾きは **30 ÷ 150 = ＋0.20 g/℃** になります。二つの差が同じ向きに出ると積がプラスになるので、この例では温度が上がる方向に沿って予測値も上がります。

<details>
<summary>なぜこの傾きで二乗和が最小になるのか</summary>

25 ℃で0 gを通り、傾きを b とする直線を考えます。各行で「実測のずれ − b × (温度 − 25)」を二乗して足すと、この9件では **12 − 60b ＋ 150b²** です。12は実測のずれの二乗和、60は上で求めた30の2倍、150は温度差の二乗和です。

式を平方完成すると **6 ＋ 150 × (b − 0.20)²**。二乗した値が0になる b = 0.20 で最小です。25 ℃での予測値については、温度平均との差を足すと0になるため、傾きをどれに固定しても平均のずれ0 gに置いたときに二乗和が最小になります。

</details>

## 3. 測定1から、9件の比較までを追う

測定1は20 ℃で、100 gのおもりが98 gと表示されたので、実測のずれは−2 gです。平均モデルなら予測は0 g、直線なら **0 ＋ 0.20 × (20 − 25) = −1 g** です。

| 測定1 | 平均モデル | 直線 |
| --- | ---: | ---: |
| 予測 | 0 g | −1 g |
| 残差（実測 − 予測） | −2 g | −1 g |
| 残差の二乗 | 4 g² | 1 g² |

[Pythonコード](fit_line.py)では、この1行に起きた変換を、同じ順番で全9件に行います。

1. **列を読んで、温度とずれを作る。** CSVの値は文字列なので、`int(...)` で数に変えます。測定1は `temperatures` の先頭に `20`、`offsets` の先頭に `-2` として入ります。
2. **各行の平均との差を作る。** `temperature - temperature_mean` で先頭の `20` は `-5` になります。`zip(temperature_diffs, offset_diffs)` は、同じ行の二つの差を組にする処理です。最初は `(-5, -2)` が組になり、掛けると `10` です。全行の積の合計 `cross_sum` を、温度差の二乗和 `square_sum` で割って傾きを出します。
3. **対応する実測と予測を比較する。** `zip(offsets, line_predictions)` は、最初に実測 `-2` と直線の予測 `-1` を組にします。その差を二乗した `1` を、残り8件の計算結果に足します。平均モデルも同じ9件で計算します。

## 4. 結論と次の問い

**この9件では、温度を使う直線を次の比較に残す理由があります。** 二乗和は12 g²から6 g²になりました。温度別にずれの中心が変わるように作ったデータで、直線はその違いを拾えています。各温度の測定ごとのばらつきは残りました。

ここでの比較は、傾きを決めたのと同じ9件に対するものです。平均モデルは「傾き0の直線」でもあるので、傾きを選べる方法は、このデータ上の二乗和では平均モデルより悪くなりません。次の測定で役立つかを判断するには、同じ9件を比べ直しても答えは出ません。

復習するなら、**28 ℃で量るとき**に各モデルはいくつを予測するか、その時点で二つの予測のどちらが正しいか判断できるか、考えてみてください。
